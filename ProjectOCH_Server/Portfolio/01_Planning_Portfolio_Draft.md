# Project OCH | 기획 포트폴리오 초안

Updated: 2026-07-29.

## 한 줄 소개

**헥사 타일 위에서 이동, 스킬, 방향, 자원, 반응 공격을 조합하는 서버 권한형 턴제 전술 전투 게임**을 설계하고 구현하고 있습니다.

## 프로젝트 개요

| 항목    | 내용                                                   |
| ----- | ---------------------------------------------------- |
| 장르    | 헥사 그리드 기반 턴제 전술 전투 게임                                |
| 핵심 경험 | 한 번의 이동과 한 번의 일반 스킬로 만드는 위치 선점·위험 관리·반응 예측           |
| 전투 단위 | 캐릭터별 패시브, 일반 스킬 4개, 궁극기, 보조행동                        |
| 역할    | 전투 규칙 기획, 수치/스킬 데이터 설계, 서버 전투 로직 구현 및 클라이언트 연동 규격 정의 |
| 구현 환경 | Unity 클라이언트 + C++ IOCP 게임 서버 + Protocol Buffers      |

### 현재 프로토타입 범위

- CSV에는 8개 Pawn 템플릿과 45개 전투 스킬 정의가 등록되어 있다.
- Beige Ice, Beige Fire, Suen Axe, Alen Spear, Zillian Longbow는 전용 `BattlePawn` 파생 클래스로 구현되어 있다.
- Zillian Longbow는 피격 반응과 화살 기반 보조 스킬의 명중 판정을, Alen Spear는 `LINE_2` 대상 영역을 전용 클래스에서 처리한다. 공용 피해·회복·상태·밀쳐내기 규칙은 CSV 효과와 공용 실행기가 처리한다.
- 필드 입장·이동·PvP 초대·전투방 전환·결과 후 필드 복귀까지의 흐름이 서버에 구현되어 있다.

## 1. 해결하려 한 문제

전술 게임은 선택지가 많을수록 재미있지만, 플레이어가 결과를 예측하기 어려우면 복잡함만 남는다. Project OCH는 다음 세 가지 원칙을 전투 규칙으로 삼았다.

1. **한 턴의 선택을 선명하게 만든다.**
   - 이동 1회와 일반 스킬 1회가 기본 단위다.
   - 궁극기는 전투당 1회, 보조행동은 턴당 1회로 분리해 일반 스킬 선택과 경쟁하지 않게 했다.
2. **위치 자체가 전투 자원이 되게 한다.**
   - 헥사 좌표, 바라보는 방향, 백어택, ZOC를 사용해 같은 피해량이라도 위치에 따라 가치가 달라지게 했다.
3. **복잡한 규칙도 화면에서 예측 가능해야 한다.**
   - 서버가 최종 판정하되, 클라이언트는 사거리·범위·ZOC 위험·반응 순서를 미리 보여 준다.

## 2. 핵심 전투 설계

### 행동 경제

| 행동 | 제한 | 설계 의도 |
| --- | --- | --- |
| 이동 | 턴당 1회 | 위치 선정의 비용을 명확히 함 |
| 일반 스킬 (slot 2~5) | 턴당 1회 | 공격·제어·이동기 사이의 선택을 만듦 |
| 궁극기 (slot 6) | 전투당 1회 | 전투 흐름을 바꾸는 결정적 선택 |
| 보조행동 (slot 7) | 턴당 1회 | 일반 스킬을 희생하지 않는 보조 전략 |

### 위치와 방향

- 모든 전투 계산은 축좌표(hex axial coordinate)에서 처리한다.
- 캐릭터의 방향을 기준으로 후방 3방향에서 공격하면 백어택으로 판정한다.
- 원거리 공격도 백어택이 가능하게 해, 안전 거리만이 아니라 사선과 진입 경로를 고민하게 했다.

### 구현 근거: 육각 공간 알고리즘

위치 기반 규칙을 감각적인 예외 처리로 만들지 않기 위해, 모든 전투 판정을 육각 축좌표 계산으로 통일했다.

- cube distance로 사거리·인접·범위를 계산한다.
- 6방향 벡터의 내적 비교로 대상이 어느 방향 부채꼴에 있는지 판정한다.
- 같은 원리로 ZOC, 백어택, 일직선 공격 범위를 공유한다.

이 방식은 맵을 매번 탐색하지 않고도 거리와 방향을 상수 시간에 계산하게 해, 기획 규칙과 서버 판정·클라이언트 프리뷰가 같은 좌표 원리를 사용하도록 만든다.

### ZOC: 이동 위험을 만드는 규칙

ZOC는 단순한 이동 불가 영역이 아니라, **위험을 감수하고 자리를 바꿀지**를 묻는 규칙이다.

- 현재 ZOC 프로필 등록: Suen Axe는 전방 부채꼴 1칸, Alen Spear는 전방 부채꼴 2칸
- 적 Pawn이 자신의 이동 시작 위치에서 ZOC 안에 있었다면, 목적지와 관계없이 이동 시 ZOC 공격이 발생한다.
- ZOC 공격은 기본적으로 단발성 기회 공격이다. 일반 스킬의 반격 연쇄와 분리해 이동 한 번이 과도하게 긴 경합으로 변하지 않게 했다.
- 캐릭터별 사거리·반응 횟수·트리거는 프로필로 확장 가능하게 설계했다.

### 자원과 상태이상

| 시스템 | 규칙 | 플레이 경험 |
| --- | --- | --- |
| 냉기/열기 | 스킬 사용으로 누적, 턴 시작에 감소, 고수치에서 페널티 | 강한 스킬 연계와 자원 과열 사이의 리스크 관리 |
| 사기 | BaseWill 기반 최대치와 현재치를 보유 | 의지력이 제어 저항과 장기전 안정성에 연결 |
| 어지러움 | 스택 4 도달 시 의지력·사기 기반 저항, 실패 시 다음 자기 턴 행동 불가 | 즉시 스턴보다 예측·대응 가능한 누적 제어 |
| 방어력/보호막 | 보호막 → 방어력 → HP 순으로 피해 흡수 | 탱커와 반격 규칙의 방어적 선택지 |

## 3. 캐릭터 설계 사례

### Beige Fire: 과열을 감수하는 범위 마법사

- 파이어볼, 중심 피해가 강한 익스플로전, 일직선 화염벽, 불타는 타일로의 텔레포트로 공간을 장악한다.
- 스킬 사용마다 열기가 쌓이고, 고열 상태에서 턴을 넘기면 피해를 받는다.
- 궁극기에서는 과열 페널티를 무시하고 공격력을 높여 짧은 폭발 구간을 만든다.

**기획 의도:** 광역 피해량이 아니라, 화염 타일을 통해 다음 턴의 이동 경로까지 설계하는 캐릭터로 만들었다.

### Suen Axe: 무기 상태가 선택을 바꾸는 근접 하이브리드

- 도끼를 던지면 AxeOff 상태가 되고, 도끼가 떨어진 타일에서만 회수할 수 있다.
- AxeOn/AxeOff에 따라 사용할 수 있는 스킬과 회피 성격이 달라진다.
- 근접 공격의 회피·방어 성공 시 반격 체인이 발생해, 인접 전투의 긴장감을 만든다.

**기획 의도:** 단순한 쿨다운이 아니라 필드에 남은 장비 위치가 다음 행동을 제한·유도하도록 설계했다.

### Alen Spear: 넓은 전방 통제의 구현 사례

- 창병 역할(`SPEAR`)과 2칸 전방 ZOC를 CSV 프로필로 분리해 정의했다.
- `LINE_2`는 Alen Spear 전용 대상 영역으로 처리하고, 해당 스킬 데이터는 밀쳐내기와 연쇄 피해 효과를 조합한다.
- 파수꾼은 `ALLY_ATTACKED_IN_ZONE`에 연결 가능한 ZOC modifier 형태로 설계했고, 돌격 명령과 사기 증감은 공용 상태·자원 효과를 사용한다.

## 4. 클라이언트 UX 원칙

- 스킬 버튼을 누른 뒤, 대상 타일 또는 자신의 타일을 한 번 클릭해 발동한다.
- 이동 후보 타일을 가리키면 **목적지가 아니라 현재 위치** 기준으로 ZOC 반응 위험을 계산한다.
- 반응 공격과 반격은 서버의 `logs` 순서대로 0.25초 단위 연출 큐에 넣고, 재생 중 입력을 잠근다.
- 상태이상, 자원, 보호막, 다중 대상 결과는 모든 Pawn delta를 반영한다.

## 5. 구현·검증 현황

### 구현됨

- Beige Ice / Beige Fire의 데이터 기반 스킬 흐름
- Suen Axe의 무기 상태, 장비 낙하·회수, 근접 반격 체인
- 방어력·보호막·HP 피해 순서와 회피 판정
- 사기, 어지러움, 스턴의 공용 전투 기반 (`APPLY_DIZZY`는 아직 캐릭터 스킬 데이터에 연결 전)
- 일반 근접 및 창병 ZOC 프로필, 이동 반응, 아군 피격 반응용 확장 훅
- PvE/PvP 전투 입장, 턴 진행, 사망, 결과 동기화

- Unity 실전 화면에서 ZOC/밀쳐내기/사기 효과의 프리뷰와 서버 결과 일치 확인
- 전투 시뮬레이션 테스트를 통한 상태 지속시간·반응 순서 회귀 검증

## 6. 포트폴리오 발표 구성 제안

1. 30초: “이동 자체에 위험을 부여한 헥사 전술 전투”라는 한 줄 소개와 짧은 전투 영상
2. 1분: 이동/일반 스킬/궁극기/보조행동의 행동 경제
3. 1분: ZOC와 방향·백어택으로 만들어지는 위치 선택
4. 1분: Beige Fire 또는 Suen Axe 사례로 규칙이 캐릭터 정체성으로 연결되는 과정
5. 1분: 서버 권한 판정과 클라이언트 예측/연출 분리
6. 30초: 검증 결과와 다음 개선 계획

## 기획자 자기소개 문장 초안

> 저는 규칙을 많이 만드는 기획자보다, 플레이어가 한 턴 안에 의미 있는 고민을 하도록 규칙 사이의 비용과 보상을 설계하는 기획자입니다. Project OCH에서는 이동·방향·자원·반응 공격을 하나의 선택 구조로 묶고, 그 규칙을 서버 권한 구조까지 직접 구현하며 기획의 실행 가능성을 검증했습니다.
