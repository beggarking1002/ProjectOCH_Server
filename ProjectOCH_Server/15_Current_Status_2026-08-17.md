## 로그인과 계정

### Google 로그인

- 클라이언트가 Google 인증을 진행하고 서버가 인증 결과를 검증한다.
- Google의 고유 subject를 `account_identities`에 저장하고 게임 내부 `account_id`와 연결한다.
- 이메일이나 표시 이름이 달라져도 Google subject가 같으면 같은 게임 계정으로 복구한다.
- Google 토큰과 비밀번호는 DB에 저장하지 않는다.
- 동일 Google 계정의 동시 접속을 거부한다.
- 개발용 로그인도 `playerindex != 0`을 요구하며 같은 개발용 ID의 중복 접속을 거부한다.

로그인 후 `account_id`, 골드, 명성, 포만도, 인벤토리, 상점 상태와 퀘스트 상태를 불러온다. 포만도 73에서 종료한 뒤 재로그인했을 때 73으로 복구되는 영속성 검증을 완료했다.

### 개발용 계정 초기화

- 계정과 Google identity는 유지한다.
- 플레이어 프로필, 인벤토리, 개인 상점 재고, 재입고 시간과 퀘스트 진행을 초기 상태로 되돌린다.
- 서버가 개발 빌드일 때만 사용할 수 있다.
- Release 서버에서 요청하면 `player data reset is available only in development builds`로 거부한다.

## DB와 안정성

현재 마이그레이션은 다음 순서다.

| 버전 | 파일 | 책임 |
| ---: | --- | --- |
| 001 | `001_initial_schema.sql` | 계정, 외부 identity, 플레이어 프로필, 인벤토리, 마을 재고 |
| 002 | `002_player_shop_state.sql` | 개인별 상점 재입고 경과 시간과 세대 |
| 003 | `003_player_profile_account_fk.sql` | 프로필에서 계정으로 외래키 추가 |
| 004 | `004_player_quests.sql` | 플레이어별 퀘스트 상태와 목표 진행도 |
| 005 | `005_player_quest_instances.sql` | 플레이어별로 생성된 게시판 퀘스트 인스턴스·목표·보상 |
| 006 | `006_account_fame.sql` | 계정 단위 명성 및 기존 퀘스트 명성 보상 보정 |
| 007 | `007_field_pawn_class.sql` | 계정별 Field Pawn 클래스 선택값 |

### 안정성 보강 사항

- 이미 적용된 마이그레이션은 SHA-256 체크섬으로 변조 여부를 확인한다.
- 마이그레이션 파일 또는 적용 이력의 버전이 1부터 연속되지 않으면 서버 시작을 거부한다.
- 포만도 틱, 상점, 퀘스트, 전투 보상이 같은 플레이어 경제 상태를 동시에 수정하지 않도록 플레이어 단위 mutex를 사용한다.
- PvP 약탈은 승자와 패자의 프로필·인벤토리를 하나의 MySQL 트랜잭션으로 저장한다.
- 두 플레이어 중 한쪽이라도 저장에 실패하면 DB와 메모리 변경을 함께 롤백한다.
- 필드 퇴장, 연결 종료와 서버 정상 종료 시 저장한다.
- 세션 목록 잠금을 잡은 채 DB I/O를 수행하지 않도록 세션 snapshot을 사용한다.

아이템 원본은 DB가 아니라 `Data/Item.csv`다. DB의 인벤토리 행은 `item_id`와 플레이어별 런타임 수량·유통기한만 저장한다.

## 필드 이동과 마을

### Field Pawn 선택

- FieldSceneHUD의 `PlayerEmblem`을 누르면 기존 전투 클래스 선택 prefab을 단일 선택 모드로 재사용한 UI가 열린다.
- Suen, Beige, Alen, Zillian의 구현된 두 클래스씩 총 8개 엠블렘 중 하나를 선택한다.
- 선택은 `C_FIELD_PAWN_SELECT`로 서버에 요청한다.
- 서버는 지원 클래스와 필드 입장 상태를 검증하고 `player_profiles.field_pawn_class`에 즉시 저장한다.
- 성공한 `S_FIELD_PAWN_SELECT`는 같은 필드에 있는 모든 플레이어에게 방송되어 다른 클라이언트도 외형을 교체한다.
- 신규 입장과 기존 플레이어 동기화는 `ObjectInfo.field_pawn_class`를 사용한다.
- 클라이언트는 클래스별 `Pawn_*` Addressable prefab을 사용한다.
- 이동 중 선택되면 현재 이동 연출이 끝난 뒤 외형을 교체하여 보간 경로를 끊지 않는다.
- 선택값은 재로그인 후 유지되며 개발용 진행 데이터 초기화 시 기본 `Beige Ice`로 돌아간다.

관련 패킷 ID는 `C_FIELD_PAWN_SELECT = 1048`, `S_FIELD_PAWN_SELECT = 1049`다.

### 서버 권위 이동

- 필드 이동 요청의 시작점과 목적지를 서버가 검증한다.
- 직선 경로가 막히면 walkmap을 기준으로 A* 경로를 계산한다.
- block tile과 village tile은 모두 통과하거나 올라설 수 없는 장애물이다.
- 마을 너머를 클릭하면 마을 영역을 피해 우회한다.
- `S_MOVE`는 최종 목적지뿐 아니라 순차 waypoint 경로와 `duration_ms`를 보낸다.
- 이동 시간은 전체 경로 길이와 고정 속도 `3.2 world units/sec`를 기준으로 계산한다.
- 클라이언트는 현재 화면 위치에서 남은 거리만큼 보간 시간을 다시 계산해 연속 클릭에도 일정 속도를 유지한다.
- 새 목적지를 클릭하면 이전 목적지 도착을 기다리지 않고 최신 목적지로 갱신한다.

이동 방향과 공격 방향 모두 대상의 좌우 관계를 기준으로 Pawn facing을 갱신한다. axial 좌표에서 x가 같을 때도 y의 증감으로 방향을 결정한다.

### 마을 입장

- 마을 영역의 원본은 `Data/Maps/Field_001.walkmap.json`의 `village_areas`다.
- 별도 `VillageTile.csv`는 사용하지 않는다.
- 서버는 요청한 맵에 플레이어가 실제 존재하는지, 클릭 좌표가 마을 타일인지, 플레이어와 마을의 거리가 상호작용 범위 안인지 검증한다.
- 성공 시 `Village.csv`에서 이름과 설명 등 콘텐츠 정보를 찾아 반환한다.
- 현재 마을은 Eastgate, Northwatch, Riverside, Southport, Westfield 다섯 곳이다.

## 경제·인벤토리·상점

### 포만도와 게임 시간

- 현실 10분은 게임 1일이다.
- 원정대 전체 포만도는 최대 100이며 현실 1분마다 8 감소한다.
- 포만도와 유통기한은 로그인하여 접속 중일 때만 흐른다.
- 포만도가 60 이하가 되면 식품을 자동 소비해 80 이상을 목표로 회복한다.
- 자동 소비 우선순위는 유통기한 임박, 포만도 회복량이 작은 식품, 먼저 획득한 배치 순이다.
- 포만도가 80을 조금 넘는 것은 허용하되 최대 100을 넘지 않는다.
- 식량이 없을 때의 추가 필드 디버프는 아직 기획하지 않았다.

### 식품 스택과 유통기한

- 서버와 DB는 구매 시점과 남은 유통기한이 다른 배치를 별도 stack으로 보관한다.
- 클라이언트 인벤토리는 같은 `item_id`를 하나의 품목으로 합쳐 표시한다.
- 마우스오버 상세 UI에서 유통기한별 수량을 나누어 보여준다.
- 빠르게 연속 구매해도 화면에서는 같은 품목으로 집계된다.
- 인벤토리 수량 제한은 당분간 없다.

### 개인별 상점 재고

- 상점 재고는 전 서버 공용이 아니라 플레이어마다 분리된다.
- 첫 로그인에는 각 마을의 재고가 가득 찬 상태로 시작한다.
- 재입고 주기는 접속 시간 70분이며 로그아웃 중에는 흐르지 않는다.
- 재입고 시 식료품과 교역품을 모두 최대치로 완전 복구한다.
- 플레이어가 마을에 판매한 물건은 마을 판매 재고에 추가하지 않는다.
- 마을의 매입 수요는 현재 무제한이다.
- 식료품은 되팔 수 없다.

### 교역품 가격과 판매 제한

- 고가 판매처에서는 산지 구매가 대비 50% 이익을 적용한다.
- 그 외 허용된 마을에서는 10% 이익을 적용한다.
- 산지 마을에는 되팔 수 없다.
- 해당 교역품을 원래 판매하는 마을에도 되팔 수 없다.
- 계산 결과의 소수점은 반올림한다.

## 퀘스트와 명성

### 게시판 퀘스트 풀

모든 마을이 같은 퀘스트 템플릿 풀을 공유하고, 서버가 플레이어별 퀘스트 인스턴스를 생성한다.

| 템플릿 | 목표 | 골드 | 명성 |
| --- | --- | ---: | ---: |
| 교역로 답사 | 다른 마을 방문 | 50 | 5 |
| 식량 보급 | 목적지 마을에 식료품 5개 전달 | 80 | 8 |
| 판로 개척 | 목적지에서 산지 교역품 3개 판매 | 120 | 12 |

- 출발 마을과 목적지 마을이 같아지는 조합은 생성하지 않는다.
- 목적과 맞지 않는 식료품·교역품 조합도 후보에서 제외한다.
- 퀘스트를 수락하기 전에 보유한 아이템도 목표에 인정한다.
- 완료와 보상 수령은 지정된 완료 마을에서 서버가 검증한다.
- 보상을 받으면 완료 카드를 제거하고 퀘스트 풀에서 새 카드를 채운다.
- 재로그인이나 서버 재시작으로 게시판 퀘스트가 임의로 다시 뽑히지 않도록 생성 인스턴스를 DB에 저장한다.
- 계정 하나가 동시에 진행할 수 있는 퀘스트는 최대 3개다.

### 퀘스트 포기

- FieldSceneHUD의 진행 중 퀘스트 UI에서 포기할 수 있다.
- 골드 위약금은 원래 골드 보상의 2배다.
- 명성 위약금은 원래 명성 보상의 2배다.
- 골드가 부족하면 포기할 수 없다.
- 명성은 음수가 될 수 있다.
- 포기된 퀘스트는 진행 목록에서 제거되고 게시판 슬롯을 다시 채울 수 있다.

### 명성

- 기존 마을별 평판 대신 계정 전체가 공유하는 `fame` 하나를 사용한다.
- 퀘스트 보상과 PvP 전투 승리로 증가한다.
- PvP 전투 승리 보상은 현재 명성 10이다.
- 현재 명성은 쌓여 가는 수치 자체를 즐기는 요소이며, 상점 할인이나 해금 등의 혜택은 구현하지 않는다.
- 명성이 음수라면 전투 시작 시 모든 아군 Pawn의 현재 사기를 최대 사기의 50%로 설정한다.

## 전투 입장과 공통 규칙

### 클래스 선택과 로스터

- 한 플레이어가 다른 플레이어에게 전투를 신청하고 상대가 수락하면 양쪽에 클래스 선택을 시작한다.
- 각 플레이어는 Suen, Beige, Alen, Zillian 네 캐릭터마다 두 클래스 중 하나를 선택한다.
- 선택한 네 클래스로 BattleRoom에 입장한다.
- 디버그 `B` 전투 진입도 즉시 입장하지 않고 같은 클래스 선택 UI를 거친다.
- 프로토콜은 기존 클래스 선택 패킷을 재사용한다.

### 행동 구조

- 현재 전투는 AP 수치 대신 `이동 가능 여부`와 `일반 스킬 사용 여부`를 별도로 관리한다.
- 기본적으로 자기 턴에 이동 한 번과 일반 스킬 한 번을 사용할 수 있다.
- 서버가 턴, 소유권, 이동 가능 여부, 스킬 사용 여부, 사거리, 대상, 점유와 지형을 최종 검증한다.

### 이동·지형·피해

- 전투 이동도 목적지까지의 실제 타일 경로를 순서대로 밟는다.
- 이동 경로 중간의 불 타일을 포함해 밟은 모든 불 타일에서 피해를 처리한다.
- 경로와 Pawn delta, 타일 delta, 행동 로그를 클라이언트에 보낸다.
- 실드 총량의 최대치는 최대 체력과 같다.
- Tanker 계열은 전투 시작 시 armor 실드를 최대치로 채운다.

### ZOC·반격·경합

- 근접 캐릭터의 ZOC는 `BattleZoc.csv`를 원본으로 사용한다.
- 과거 클래스별 하드코딩 대신 CSV의 클래스·역할 규칙으로 통합했다.
- 모든 Melee, Tanker, Spear 직업군은 반격할 때 슬롯 2, 즉 첫 번째 일반 공격 스킬을 사용한다.
- 반격 가능 거리, 생존 여부, 직접 공격 여부와 반격 연쇄 제한을 서버가 검사한다.
- Alen Shield와 Alen Spear 조합에서 누락되던 반격 조건을 행동 로그로 추적할 수 있도록 진단 로그를 보강했다.

### 어지러움

- 어지러움은 별도 누적 자원이 아니라 부여 시 스턴 확률을 판정하는 공통 메커니즘이다.
- 공격자의 `BaseFocus`와 피격자의 `BaseWill`이 스턴 확률에 영향을 준다.
- Alen과 Zillian Mace가 발생시키는 어지러움도 같은 공통 판정을 사용한다.
- Zillian Longbow의 피격 반응처럼 공격자에게 되돌려 주는 경우에는 반응 주체의 Focus와 공격자의 Will로 판정한다.

## 구현된 클래스 관련 변경

### Alen Shield

- Alen Spear와 같은 패시브·보조행동은 공용 스킬 행을 공유한다.
- 패시브 `카르바스 가문의 의지`: 사기 감소량을 30%만 적용한다.
- 슬롯 2 `노력`: 인접 검 평타이며 반격에도 사용한다.
- 방패술은 반격 태세와 피해 경감 태세를 토글한다.
- `책임감`: 인접 아군 대신 맞기, 위치 변경, 방어력 증가를 제공한다.
- `자존심`: 최대 2칸 돌진하며 적을 밀어낸 뒤 Alen도 비워진 자리로 이동한다.
- 궁극기 `결투의 대가`: 방어력 50%를 근력으로 바꾸는 4턴 자기 버프다.
- 특정 적 지정과 추가 피해 배율 퍽은 현재 제외했다.

자세한 구현 메모는 [[13_Alen_Shield_Implementation]]을 참고한다.

### Zillian Mace

- 피격 시 공격자에게 공통 어지러움 판정을 수행한다.
- 기본 평타, 약한 피해와 어지러움, 광역 실명, 인접 광역 회복을 구현했다.
- 궁극기는 현재 체력 절반을 소비해 아군 전체에 보호막을 부여한다.
- 보조행동은 인접 아군 회복·정화 후 요청에 따라 위치를 교환한다.

자세한 구현 메모는 [[14_Zillian_Mace_Implementation]]을 참고한다.

### Suen Parvis

- Parvis Off 상태에서 슬롯 2는 Seated Shot, 슬롯 3은 Stand Shot이다.
- Parvis On과 Off 모두 슬롯 3은 Stand Shot으로 유지한다.
- Parvis On 상태에서는 보조행동을 제한한다.

### 기타 현재 로스터

- Suen Axe, Beige Ice, Beige Fire, Alen Spear, Zillian Longbow가 데이터 기반 전투 파이프라인에 연결되어 있다.
- 기본 전투 Pawn 시각 리소스는 `beige_fire` 대신 `beige_ice`를 사용하도록 변경했다.
- 스킬 아이콘과 walk 아이콘은 새 규격 리소스로 교체했고 `Alen_Sword_Passive` 파일명 오류를 정정했다.

## 전투 시작 페널티와 승리 약탈

### 포만도 페널티

| 전투 시작 포만도 | 모든 아군 Pawn의 시작 HP |
| ---: | ---: |
| 51 이상 | 최대 HP 100% |
| 21~50 | 최대 HP 70% |
| 0~20 | 최대 HP 50% |

- 20 이하에서는 50 이하 페널티와 중첩하지 않고 더 강한 50% 손실만 적용한다.
- 최소 HP는 1이다.
- armor와 barrier는 HP 페널티의 영향을 받지 않는다.

### PvP 승리 보상

- 승자는 패자의 인벤토리에 있는 `TRADE` 유형 교역품을 전량 가져간다.
- 식료품과 다른 아이템 유형은 약탈하지 않는다.
- 승자는 명성 10을 얻는다.
- 전투 결과 패킷은 교역품 ID, 표시 이름, 수량과 명성 보상을 전달한다.
- 클라이언트 결과 UI는 승자의 `약탈`과 패자의 `약탈당함` 목록을 구분해 표시한다.
- 약탈 후 양쪽 원정대 상태를 다시 동기화하고 퀘스트의 인벤토리 목표를 재평가한다.
